# SQL queries

| File | Description |
|---|---|
| `01_rental_prices.sql` | Shows the latest saved quote for each offer's newest version, along with the GPU, price, location and reported availablity. This makes it easy to comapre listings while keeping unknown values visible. |
| `02_gpu_catalog.sql` | Lists each GPU model with its memory, listing count, provider count and lowest recorded USD price. It's a quick overveiw of the hardware in the database and when its quotes were last udpated. |
| `03_provider_summary.sql` | Breaks down each porvider's listings into available, unavailable and unknown groups. It also shows the lowest recorded USD price, so we can see what each provider has in the latest saved observatons. |
| `04_offer_history.sql` | Shows saved prices over time and compares each quote with the previous one for the same offer version. It calculates the precentage change when currencies match and there is a valid earlier price, which helps us spot price movments. |
| `05_workload_summary.sql` | Groups jobs by GPU type and trace priority, then shows job counts, durations and estimated GPU-hours. The calcuation treats the GPU request as the whole-job amount and does not mulitply it by worker count. |
| `06_organization_demand.sql` | Summarizes each organization's job count, priority mix, GPU types and estimated GPU-hours using the same whole-job request assumption. It helps us compare demand across organizatons, while submission times stay in the trace's realtive seconds. |
| `07_workload_market_coverage.sql` | Checks how much of each organization's workload has an exact GPU match with an available, priced USD rental in the latest saved capture from each source. It keeps unmatched jobs in the totals and shows which GPU types are unmmaped or have no matching qoute, without assuming enough stock exists. |
| `08_organization_price_exposure.sql` | Estimates each organization's cost under the lowest, median and highest matching quote, treating GPU requests as whole-job demand. These are scenraios using saved prices rather than historical bills, and the results also show unpriced jobs and spending concetration. |
| `09_spot_on_demand_comparison.sql` | Compares spot and on-demand costs for the same matched jobs, using whole-job GPU requests and the latest saved quotes. It reports possible savngs and gaps in mode coverage; these are cost comparisons, not a promise that either option is availabe in the required quantity. |
| `10_budget_allocation_scenario.sql` | Builds a job shortlist under a shared budget and a seperate spending cap for each organization, using estimated costs from whole-job GPU requests. Organizations take turns, skipped jobs use no budget, and this is a greedy cost scenario rather than an optimal scheduluer or a GPU reservation. |
